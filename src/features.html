概览

Caddy 本质上是一个配置管理系统，可以运行各种应用程序，如 HTTP 服务器、TLS 证书管理器、PKI 设施等。它可以通过称为配置模块的插件进行扩展。

Caddy 拥有灵活而强大的 HTTP 反向代理、在线配置 API 以及健壮、可用于生产环境的静态文件服务器，并且默认通过自动 TLS 证书为所有站点提供 HTTPS。

总体程序技术规格

编程语言

语言选择对于 Web 服务器至关重要。语言影响开发速度和难度、性能、测试、部署复杂性、生态系统可靠性、依赖项、工具、错误处理和可靠性等多个方面。Go 在所有方面都具有强大优势，可实现快速开发、稳健的生产性能和高可扩展性。
Go

内存安全保证

大多数服务器（NGINX、Apache、HAProxy 等）及其依赖项都是用 C 语言编写的，容易受到灾难性内存安全漏洞（如缓冲区溢出）的影响，例如 Heartbleed。像 Caddy 这样的 Go 程序对一整类安全漏洞具有免疫力。
强

构建产物

Caddy 直接编译为原生 CPU 指令。不需要解释器；许多指令都针对架构进行了优化。静态二进制文件也更安全，因为没有动态链接。
平台原生静态二进制

运行时依赖

Caddy 是静态编译的。动态链接的应用程序在生产环境中容易崩溃，并且可能更不安全，因为共享的可执行资源从系统的各个位置加载。通常，Caddy 二进制文件不一定需要外部库——甚至不需要 libc。
无

编译时间

在消费级硬件上，标准 Caddy 构建只需几秒钟。这对于快速迭代、插件开发和低成本的部署至关重要。其他用 C/C++ 编写的服务器可能需要几分钟。
~30 秒冷编译，
~2 秒热编译

自动 HTTPS

我们的旗舰功能，由 CertMagic 驱动。Caddy 是第一个也是唯一一个默认启用 HTTPS 的主要服务器，并自动为所有站点获取和续期证书。

完全原生、集成的自动 HTTPS 远远优于任何需要外部工具或 cron 任务的解决方案。Caddy 的证书维护是业界最佳的，因为它比任何其他解决方案更健壮、更可靠、更具可扩展性。Caddy 简化了你的基础设施，而不是使其复杂化。

当然，你可以尝试使用 Certbot 和 cron 任务部署 100,000 个站点——但如果它自己不会崩溃，Web 服务器也会崩溃。只有 Caddy 被设计为在水平和垂直方向上大规模扩展 TLS 证书。

再也不用手动生成 CSR。再也不用点击电子邮件中的链接下载证书。再也不用（错误地）配置 Web 服务器来使用它们。再也不用错过在证书到期前每隔几个月逐一续期的提醒。你甚至不需要考虑证书或 TLS。

这真是自动魔法。

合规性

Caddy 的 TLS 默认配置是安全的，无需额外配置，并通过各种行业的合规测试。
  • 符合 PCI DSS
  • 符合 NIST
  • 符合 HIPAA
  • 行业最佳实践

按需 TLS

服务不属于你的域名？或者有很多域名？没问题！只需几行配置，按需 TLS 在 TLS 握手期间动态获取证书，将你的部署扩展到数万个证书。此功能是 Caddy 独有的。

证书颁发机构

以兼容的方式从任何颁发机构获取证书。证书颁发机构接收 CSR 并返回证书资源。大多数站点只需使用 ACME 获取证书。但 Caddy 也可以为内部使用、测试或开发颁发自己的自签名证书。Caddy 的颁发者来源是可插拔的，因此 Caddy 可以从任何颁发者模块自动获取证书。
  • ACME

OCSP

OCSP 指示证书何时被吊销。服务器应将 OCSP 响应装订到证书上，以向客户端提供更好的安全性和隐私。Caddy 是第一个也是唯一一个默认自动执行此操作的服务器。它还缓存响应以应对 OCSP 响应者故障，并在集群中共享。如果需要，可以禁用它。
自动 OCSP 装订并缓存

必须装订

Caddy 可以获取强制 OCSP 装订的证书（如果 CA 支持）。这可能在吊销情况下提供更高的安全性。

吊销处理

被吊销的证书会自动替换。由于 Caddy 装订并刷新 OCSP 响应，它可以检测到你的证书是否已被吊销，如果是，则将其替换为新的证书。

会话票据加固

如果攻击者窃取了加密会话票据的密钥，TLS 连接就毫无意义。Caddy 已被学术界引用为唯一定期轮换这些密钥以限制攻击窗口的服务器。

证书生命周期

大多数 ACME 客户端假设 90 天证书，或不期望短于 7 天的证书。Caddy 可以成功管理生命周期为小时和分钟级别的证书。

Caddy 没有硬编码续期前的特定年龄，而是根据每个证书的生命周期计算相对年龄，称为续期窗口比率。默认情况下，Caddy 在证书可用生命周期的 2/3 时续期。此比率适用于大多数有效期，但可以调整。

任何生命周期

智能错误处理

如果 Caddy 无法获取证书，会记录错误，并且 Caddy 将指数退避并重试，直到成功（通常最多 30 天，但可能更长）。Caddy 尽一切合理努力保持你的证书续期。
指数退避

内置限流

Caddy 遵循最佳实践，不会向 CA 发送大量证书请求；相反，每个订单都经过精心计时，以避免压倒 CA 服务器。

反向代理

使 Caddy 代理独一无二的是其设计。只有面向客户端的一端需要是 HTTP；与后端往返的基础传输可以使用任何协议！

此外，我们的代理可以使用高度动态的上游。也就是说，可用的上游可以在请求进行中更改！如果没有后端可用，Caddy 可以保留请求直到有可用为止。
