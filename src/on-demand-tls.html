您刚刚享受了服务
... 由 Caddy 动态颁发的 TLS 证书！

发生了什么？

Caddy 自动为您的域名 {{.Req.Header.Get "X-Forwarded-Host"}} 获取了证书，无需修改服务器配置。我们将这项技术称为按需 TLS（On-Demand TLS），这是 Caddy 的独家功能。

使用按需 TLS，无需更改配置即可通过 HTTPS 提供更多域名服务。这对于托管客户自有域名内容或 API 的服务器来说非常理想，因为您的 HTTPS 部署能够随业务的发展而扩展。

Caddy 的技术是许多提供自定义域名的 SaaS 产品的秘密武器。它每年能产生数十万美元的收入，同时为企业节省数万美元的开发和维护成本。

趣闻：2015 年和 2016 年该功能首次推出时，曾在多个技术演示现场赢得全场起立鼓掌。

为客户域名轻松实现自托管 HTTPS

使用按需 TLS，几分钟内即可发展您的自定义域名 SaaS 业务。最小配置如下：

1. 防止滥用

首先，您需要配置一个内部端点，Caddy 可以“询问”该端点是否允许为某个域名颁发证书。该端点通常在列表或数据库中查找域名，如果允许则返回 HTTP 200。请务必拒绝不认识的域名。（这意味着客户需要先告知您的应用程序他们的域名是什么。）

2. 启用按需 TLS

最后，为通配站点启用按需 TLS 即可。

实际生产配置通常会包含更多内容，但这已是为您不控制的域名提供服务所需的最小配置。剩下的只需域名所有者设置他们的 DNS 记录（如下所述）。

卓越的客户体验

对于域名所有者来说，流程更为简单：只需设置 DNS 记录。首次访问他们的网站就会自动颁发 TLS 证书。简直像魔法一样！

1. 指向 DNS 记录

客户在他们控制的域名或子域名上设置 CNAME 记录或 A/AAAA 记录，以便 他们的 域名解析到 您的 服务器的 IP 地址。

# 客户的 DNS（示例域名） your-app.customer.com CNAME -> your-app.com # 您的 DNS（示例 IP） your-app.com A -> 198.51.100.1 your-app.com AAAA -> 2001:db8::

没有第二步。一旦建立连接，Caddy 便会为其域名获取并提供证书。只要有持续不断的连接，Caddy 就会自动续期证书。当连接停止后，Caddy 会让证书过期并自动删除。

这就是您每年节省数万美元开发和基础设施成本的方法。
