赞助问答

我们经常看到在商业环境中随意部署 Web 服务器带来的灾难性后果：直到问题发生才向社区求助，但此时信息不足，解决问题耗时过长——而这类事件本可以通过适当的培训和支持来减轻。

我们认为所有专业和企业用户使用 Caddy 都应投资赞助，就像我们期望树枝为树干和树根提供养分一样。我们的赞助不仅仅是“感觉良好”的捐赠。它们为公司提供关键价值，同时维持项目的持续维护。

Caddy 的原始作者 Matt Holt 经营 Dyanim, LLC，与全球社区一起维护项目并指导开发。赞助由 Dyanim, LLC 履行。

这些是软件许可证吗？

不。赞助是独立的产品，为个人、组织和公司提供支持、开发和培训服务、市场营销以及各种项目管理功能。无论赞助状态如何，你对软件的许可证保持不变。

什么是专业服务？

这些包括任何补充常规项目维护的服务，例如入职指导、培训、演示和定制开发工作。

我需要上面未列出的服务。

没问题——联系我们，告诉我们你的需求！

只能通过 GitHub 付款吗？

不是的，我们的高端层级可以接受各种支付方式，如发票、ACH、电汇，如果需要，甚至可以是纸质支票。

我们是否需要批准新的供应商？

很可能不需要！我们的赞助订阅由 GitHub 管理，而 GitHub 通常已经是大多数企业批准的供应商。

为什么是赞助？

专业人员和商业用户有众多开源许可证无法满足的需求，而更广泛的社区也有众多专有许可证无法满足的需求。例如，公司需要支持和高级功能，这些在缺乏商业关系的情况下极难提供或开发。

为了弥合这一差距，我们提供赞助，使我们的软件可以保持自由使用，同时为企业在选择如此关键的技术时提供所需的保障。

我们还有一个较低层级，适合那些没有公司资金支持、只想支持项目的个人。

我们的软件之所以有吸引力，是因为赞助使其保持完全开源，没有昂贵的付费专有功能来分割社区。相反，每个在家庭实验室或学校项目中运行 Caddy 的人，使用的都是与全球大型企业相同的软件版本。这真的很了不起，而赞助商使之成为可能。

如果我们属于某个类别但无法预算怎么办？

我们会问产品经理：为什么要在没有支持能力的情况下部署软件？也就是说，一个成熟的企业如果预算有限，可以注册 Startup 级别的赞助；这比没有任何安全网要好。但合适的赞助层级将带来更高的整体满意度，因为我们可以更好地适应你的情况。

赞助更好

公司和项目都无法仅靠开源许可证实现规模化可持续。必须建立某种商业关系来支持公司的运营以及项目的持续开发。

通常的解决方案是：为软件或特定功能收费、购买保险、聘请顾问，或安排内部开发人员学习和维护该技术。

赞助为这个问题提供了一个简单而深刻的解决方案，与替代方案相比有很多优势：

顾问

咨询费很高（$250-500/小时），以抵消该职业的不稳定性，通常按小时计费，这可能会让客户承受压力，因为他们希望尽量减少成本。

顾问各不相同，可能拥有混合技能，而不是在所涉及的主题（例如特定的 Web 服务器）上具备专业知识。你还需要在合作前将其批准为供应商。

赞助有一个可承受的固定费率，没有严格的小时限制，从而消除压力、降低成本。你直接与软件领域的世界专家联系，并且可以通过已知供应商 GitHub 付款。

保险

赞助不是保险——当发生事件时，它不会赔偿金钱，也不能被法律归类为任何形式的保险。相反，它通过全面的集成策略首先帮助减少事件发生的可能性和严重性。我们会了解你的设置，并帮助你以最佳方式部署。

与保险打交道既繁琐又昂贵，而赞助则更简单，文书工作和法律复杂性更少。

内部招聘

计算很简单：一名熟练的内部开发人员年薪可能为 $180,000。赞助的价格低一两个数量级，通常为 $3k-12k/年，并且能让你接触到世界级专家。

赞助绕过了人力资源和招聘流程，并且由于其能够培训你现有的员工，你仍然可以在内部保留这些知识。

如果员工离职，知识也常常随之流失。赞助可以确保在人员流动时，技能仍能留在组织中。

什么都不做

不言而喻，直接接触你所依赖软件的维护者 比没有支持、没有安全网、无法影响项目优先级要好。

使用开源软件，你只能靠自己。你可以向社区求助，但无法建立高关注度的关系来调整维护者的优先级。

切实的商业成果

赞助帮助你保持竞争优势、降低成本，甚至可能提高客户忠诚度。你将能够满足纯开源软件无法想象的要求。

软件保障

这不是保险。它更好。你的赞助有助于维持项目的持续开发，并且你可以直接联系维护者，安心无忧。

提高客户忠诚度

客户对那些公开赞助项目的公司更加忠诚，尤其是他们使用的项目。数万名 Caddy 用户在你赞助该项目时更有可能成为并保持你的客户。

降低成本，提高利润

通过 Caddy 赞助更高效地运营，它可以防止咨询费用、招聘开支、灾难性生产故障和低效配置。
